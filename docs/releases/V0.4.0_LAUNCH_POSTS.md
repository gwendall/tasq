### 2/5

Tasq keeps five things separate:

- the outcome still owed;
- who currently claims it;
- one execution attempt;
- the evidence produced;
- the decision that it is actually done.

An agent saying “the command passed” is not the same as finishing the task.

### 3/5

durable state instead of reconstructing the plan from chat history.

## LinkedIn

Coding agents are good at executing a task. Coordinating several of them over
time is still surprisingly manual.

A `PLAN.md` works until two agents choose the same item, a process crashes, or
“the command passed” gets mistaken for “the outcome is complete.”

I built Tasq as the durable version of that file: a local-first project tracker
shared by you, Codex, Claude Code, and any MCP client.

Tasq keeps the task, expiring claim, execution attempt, evidence, and completion
decision separate. A replacement worker can resume from the ledger instead of
replaying your chat history. The Local path is one SQLite file you own, with no
account, cloud dependency, or telemetry.

The open-source v0.4.0 public alpha is now available for macOS arm64 and Linux
x64.

Try the isolated demo:

`npx @tasq-run/cli@0.4.0 demo`

Website: https://tasq.run

Source: https://github.com/gwendall/tasq

It is deliberately early: use backups for retained ledgers and expect
documented migrations before 1.0.

## Show HN

### Title

Show HN: Tasq – a local-first project tracker shared with coding agents

### Body

Hi HN,

I built Tasq because my coding agents kept needing a durable `PLAN.md`, and the
file stopped working once several sessions or workers touched the same project.
Two agents could pick the same item, a crashed worker could look like the
current owner forever, and a successful command could be reported as if the
actual outcome were complete.

Tasq is a local-first task tracker for a human and their agents. It models a
commitment, an exclusive expiring claim, an execution attempt, evidence, and
the completion decision as separate records. That lets another worker recover
from durable state without treating an old chat transcript as coordination
truth.

Tasq Local is a JSON-first CLI, a capability-scoped stdio MCP server, and a
read-only loopback Console over one SQLite ledger. It does not launch agents or
own provider credentials. Codex, Claude Code, or any MCP client can use the
same explicit space and actor-scoped recipes.

The v0.4.0 public alpha is open source and available for macOS arm64 and Linux
x64. You can run an isolated three-second demo without installing anything or
touching existing data:

`npx @tasq-run/cli@0.4.0 demo`

Website: https://tasq.run

Source: https://github.com/gwendall/tasq

Release: https://github.com/gwendall/tasq/releases/tag/v0.4.0

I would especially value feedback on the commitment/attempt/completion split
and on what would make the first shared-agent setup legible without reading the
repository.

## Short community post

I built Tasq after `PLAN.md` stopped being enough for several coding-agent
sessions. It gives you and your agents one local ledger with exclusive expiring
claims, separate execution attempts, inspectable evidence, and explicit
completion.

It is not an agent runtime and does not hold provider credentials. It is the
project tracker the tools you already use can share.

The open-source v0.4.0 public alpha is available for macOS arm64 and Linux x64:
https://tasq.run

Isolated demo: `npx @tasq-run/cli@0.4.0 demo`

Source: https://github.com/gwendall/tasq

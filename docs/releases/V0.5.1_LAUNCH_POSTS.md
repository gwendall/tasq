# Tasq v0.5.1 launch posts

These drafts announce the published open-source public alpha without extending
its support claims. The primary action is to run the isolated demo; the
secondary action is to inspect the [source](https://github.com/gwendall/tasq)
and the immutable
[v0.5.1 release](https://github.com/gwendall/tasq/releases/tag/v0.5.1).

They replace the v0.4.0 drafts, which were never published and which led with
mechanism. ADR-022 is why: the kernel is what makes the answer trustworthy, not
what anyone is shopping for. Lead with the collision, show the fleet, and let
the machinery be the reason it is true rather than the pitch.

**Rules that survive every edit.** Do not describe Tasq as an agent runtime, a
managed cloud service, or proof that actor-provided evidence is true. Do not
imply that Local coordinates separate machines. Keep "public alpha" visible
whenever the post mentions availability. Never claim adoption that does not
exist: there are no users yet, so there are no testimonials, and the only case
study that may be cited is this project's own dogfooding. No em-dashes.

### 2/6

The claim is an expiring lease, not a flag.

If an agent dies mid-task, the lease lapses and the work returns to the pool.
Nothing to clean up, no stuck row, no daemon watching processes.

### 3/6

That is also why you can see your fleet without running one.

```
$ tasq fleet
claude-code 2.1.246 in ~/Code/api
  * rewrite the parser        lease 26m left  heartbeat 30s ago
codex 0.150.0 in ~/Code/api
  * add the regression test   lease 12m left  heartbeat 2m ago
```

It asks whether anyone still owns the work, not whether some process is alive.

### 4/6

"Done" is the other half.

An agent saying it finished is an assertion. Tasq can require an inspectable
receipt before a commitment closes, and keeps a succeeded attempt distinct from
a completed commitment. They are not the same fact.

task that rests on it.

When you learn the reason was wrong, you withdraw the sentence once. Everything
resting on it pauses. Nothing is cancelled and no history is rewritten.

## Show HN

### Title

Show HN: Tasq - a task list your coding agents share, with expiring claims

### Body

I run several coding agents on the same repository and kept hitting the same
three problems: they duplicated work, they had no idea what an earlier session
had already tried, and "done" meant whatever the agent decided it meant.

Tasq is a local-first ledger they share. The parts that turned out to matter:

**Claims are expiring leases.** An agent claims a task and the others are
refused. If it dies mid-task the lease lapses and the work returns to the pool.
That also means you can see your fleet without running a daemon over processes:
the question is whether anyone still owns the work, not whether a PID exists.

**A succeeded attempt is not a completed commitment.** They are different facts
and Tasq stores them separately. A commitment can require an inspectable receipt
before it closes.

**Work can record why it exists.** One sentence, shared by every task resting on
it. When the reason turns out to be wrong you withdraw it once, and everything
resting on it pauses rather than being cancelled, so the reasoning stays
readable.

It is one SQLite file you own, Apache-2.0, no service to sign up for. Agents
reach it over MCP or by running the CLI, which is what a shell-capable agent
already knows how to do.

Honest about the state: public alpha. Local coordinates agents on one machine
sharing one ledger; a separate server exists for remote, and managed cloud does
not. The store format moved in this release, so an existing ledger migrates
forward once and `tasq store upgrade` makes that an explicit decision.

Try it without installing anything:

    npx @tasq-run/cli@0.5.1 demo

https://tasq.run  ·  https://github.com/gwendall/tasq
